This Repo contains a tool to automatically verify the correctness of error semantic translation in Rust Wrappers for C Libraries, by statically analyzing Rust code, generating specifiations to describe the checked return values, and comparing this with C-side Error Specifications generated by ESSS (https://github.com/csl-ugent/ESSS) or and LLM.

To build the tool, set the Rust Compiler to `nightly` and run `cargo clean && cargo build`

To use it on a Wrapper, build that Wrapper with `nightly` and the tool set as `RUSTC_WRAPPER` using `cargo clean && cargo build`.

To generate an LLM Specification, clone the apprpriate C Library, then have an LLM (we used `mistral-medium-3.5` with Maximum Thinking effort) execute the prompt found in `ai_analysis_prompt.txt`, with the paths filled in as needed. Make sure the tool has already run once and generated the `ext_func_list_for_ai.txt` file, which the LLM will use as a guide. If the LLM used is not able to create and write to files itself, adjust the prompt appropriately. 

To generate an ESSS Specification, build the C Library with `wllvm` and extract the bitcode files, then run ESSS, as instructed in its README. We ran it with `musl` for our Analysis. Copy the relevant part of its output, whcih will be a long list of only functions and their error intervals, looking something like this:

Function: update_shape {return index 0}
  [-12, -1]
Function: update_shape_struct {return index 0}
  [-12, -1]
Function: publish_shape_meta {return index 0}
  [-1, -1]
Function: validate_shape_chunkshape_blockshape {return index 0}
  [-12, -1]

into `esss_results.txt` inside the Rust Wrapper directory (next to `results_ai_analysis.txt`, generated by the LLM).

If both `esss_results.txt` and `results_ai_analysis.txt` exist, the tool will correlate these two C-side specifications and use the result of that for the comparison with the Rust side; if only one exists (for example because the other one has been renamed), the tool will use that only. This way, the C-side mode can be set.

Note that the tool still contains some artifacts of earlier testing, such as support for a third C-side specification (EESI), or an output of the Rust-side specs it generates in the EESI format. These can be ignored.
